# 地图页构建（⑤ 交付 · 空间轴载体）

这份文件是 ⑤ 交付里"地图"这个载体的完整做法。产出一页**手机可用的单文件 HTML**：
点位 + 动线 + 编号 + 段间时长，现场断网也能开。

读它的时机：行程方案定案后要出图，或者图出来有问题要排查。

---

## 一、产物形态

| 要求 | 判据 |
|---|---|
| 单文件 | 一个 `.html`，双击能开，不依赖本地服务 |
| 零 CDN | 地图库内联（现场网络差，CDN 一抽风就白屏） |
| 手机优先 | 390px 宽是主要视口，地图 + 卡片上下咬合 |
| 可用 | 点位可点、可一键导航、可切天、可看总览 |
| 可校核 | 点位带**编号**、动线带**段间时长**（这是图的意义所在） |

---

## 二、构建流程

1. **复制模板**：`assets/template.html` → `index.html`
2. **填数据**：`HOTEL` 对象 + `DAYS` 数组（结构化数据来自 ①–④ 的成果）
3. **补总览**：`overviewContent()` 填行程概要、支付提示、砍点说明
4. **算路径**：OSRM 取真实路网（见第四节）
5. **定造型**：标记与皮肤（见第五、六节）
6. **自检**：语法 + 真机交互（见第八节）

### 数据结构

每个点位：

```
必填：name, lat, lng, type, time, desc
选填：key（路径映射）, num（编号）, budget, detail, pay, xhs, reserve, gmap
```

- **类型**：`food` | `spot` | `drink` | `hotel` | `transport`
- **支付提示**：`pay: 1` = 确认可用（绿）、`0.5` = 可能不行（橙）、不写 = 不显示
- **选填字段与"卡片显示名"解耦**：见第四节第 4 条（这是最容易踩的坑）

### 设计系统（可选）

默认模板是 Apple 风格（SF Pro / 浅色 / 毛玻璃）。要换风格可从
[awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 取一份 `DESIGN.md`，
然后改 `template.html` 的 `:root` CSS 变量（颜色 / 字体 / 间距 / 圆角）对齐它的 token。

> 换风格前先确认行程已过 ④ 校核——**皮肤不解决行程问题**。
> 皮肤的实操方法见第五节。

## 三、路径与坐标：四件必须做对的事

### 3.1 内联地图库，别用 CDN

把 `leaflet.js` + `leaflet.css` 直接内联进 HTML（`npm install leaflet --prefix <workspace>` 后读 `dist/`）。

> ⛔ **转义别做过头（会直接白屏）**：`template.html` 的 `overviewContent()` 里有「**外层模板字符串内再嵌模板字符串**」的写法，
> 内层必须是**裸反引号**和 `${…}`，**不能**再加反斜杠。原版一度把内层误写成 `` \` `` / `\${`，
> 浏览器直接抛 `Uncaught SyntaxError: Invalid or unexpected token` → **生成的地图打开全白屏**
> （上游 issue #2；作者已在 2026-07-08 的 PR #3 修复）。**取模板务必用上游 main 的最新版**——旧副本会把这个 bug 一路传下去。
>
> 一句话自检：抽出所有 `<script>` 丢给 `new Function(code)`，语法不过就是白屏，不用等打开页面。

### 3.2 OSRM 必须 `overview=full`

```
https://router.project-osrm.org/route/v1/driving/{lng},{lat};{lng},{lat}?overview=full&geometries=geojson
```

- 注意是 **lng,lat** 顺序；返回的 geojson 坐标也是 `[lng,lat]`，画图前要转成 `[lat,lng]`
- 落盘成 `{ "D1|A|B": {dist, coords} }`

> ⛔ **`overview=simplified` 会让路线"不像贴路"**：10km 路程只剩 20–30 个点，画出来就是**斜切街区的折线**
> （症状很容易被误读成"路径是瞎画的"）。必须 `overview=full`，再按 **8m 阈值抽稀**——
> 首尾必留 + 距上一个保留点 > 8m 才留；点数降到约 1/3，视觉上完全贴路、文件也不会爆。

### 3.3 坐标系必须转换（最隐蔽、后果最严重）

高德 / 腾讯给的坐标是 **GCJ-02**，而 OSRM 路网是 **WGS84**，两者在中国境内差 **300–500m**。

不转换 → 路径整体平移几百米 → 看上去"不贴路" → 复盘时极易误判成"OSRM 数据错了 / 地图库有问题"。

**正确链路**：

```
输入坐标 GCJ-02 → gcj2wgs() → 送 OSRM（overview=full）→ 返回 WGS84 → wgs2gcj() → 画在高德瓦片上
```

（标记点坐标本来就是 GCJ-02，不用动。）

工具：`coord.js`（`wgs2gcj` / `gcj2wgs` 迭代反解，误差 <1e-9 度）、
`recalc_routes.js`（一键重算整份地图 + 自动抽稀 + 逐段写吸附报告）。

### 3.4 路线配色：线会糊进底图

主线用 **亮红 `#ff1744`**，底下垫一层 **白色 `weight:10` 描边**。
高德浅色底图上有大块绿地和蓝色水面，单色线（尤其 iOS 绿 `#34c759`）会与绿地融为一体。
用 `L.layerGroup()` 装两层返回，`addTo(map)` / `removeLayer` 照旧能用。

### 3.5 验收：别迷信"吸附道路名对上了"

`waypoints[].name` 只能证明"在 OSRM 自己的 WGS84 世界里吸附合理"，
**证明不了画在高德瓦片上没整体偏移**。唯一可靠的验收是**看线是否压着道路**。

- 辅助手段：用吸附到的道路名反查坐标对不对（如"灵隐寺"应吸附"天竺路 / 灵隐支路"），比反复试错快得多。
- 本机 Nominatim / OSM 地理编码可能被墙，拿不到免费 geocode → 坐标用近似值 + 页面**明确标注"近似定位，导航按名称搜索"**。

### 3.6 卡片显示名 ≠ 路径 key（最易踩的坑）

卡片 `name` 为了好看会写"你的杭州酒店""西溪别院（西溪天堂）"，而 `ROUTES` 的 key 用的是规范名
→ `showDay` 里拼 key 匹配不上 → **路线静默不画**（最坏的一种失败：不报错）。

**解法**：给每个 location 加 `key` 字段做映射，`showDay` 改成 `locs[i].key || locs[i].name`。
**build 脚本必须自检**：遍历每天相邻点对，输出 `MISSING_ROUTES`，必须为 `none`。

### 3.7 生成方式

读上一版 HTML → 正则替换 `const ROUTES/HOTELS/DAYS` + `<title>` + `setView(...)` + `overviewContent()` → 写新文件。
**CSS / 交互逻辑一行不动**，最不容易出错。

## 四、标记系统

### 4.1 铁律：标记画功能

标记承载的是"**这个点在行程里是什么角色**"，不是"它讲什么内容"。

理由有两层：

1. 每天的点位必须**带编号**并与卡片一一对应——图的首要用途是核对行程是否合理（有没有折返、顺序顺不顺）；
2. 主题（历史人文 / 文学艺术 / …）种类多且会重叠，不适合做图标语义；交给**卡片标签与筛选器**。

### 4.2 造型：糖果圆

糖果圆 + 白色高光 + 左上角编号标。

- 底盘 **42×42 正圆**，`background: var(--c)` 类型色实心 + `box-shadow:0 0 0 3.6px #fff` 白环 + 投影；
  左上叠一条 17×11、`rotate(-24deg)`、`rgba(255,255,255,.6)` 的**高光胶囊**——这是"糖果感"的来源。
- 牌内 glyph 用**白色实心填充**（彩底圆盘上线条版会糊）。
- 编号在**左上角外挂**（`left:-6px; top:-6px`，白胶囊 + `0 0 0 2.6px var(--c)` 类型色环 + 深棕字 `#3A342E`），比"下挂胶囊"更醒目。
- **落地两处必须改**：
  1. `iconAnchor` 从 `[23,58]` 改成 **`[23,46]`**，让圆盘下沿贴住坐标点；
  2. `fitBounds` padding 从 40 提到 **64**——左上角编号标会凸出 `iconSize` 容器，40px 时贴边的标记会被裁。
- 代价：彩底盘 + 白环在**浅色底图上白环几乎看不见**，靠彩色圆盘本身立住，别指望白环隔开底图。
- 密度权衡：糖果圆是**单点醒目**型；若某天点位极密、圆盘互相压，改用**小圆点 + 编号胶囊**
  （密而不打架，代价是单点视觉变轻）。

### 4.3 另一条路线：深墨底牌 + 类型线性图标 + 白色编号胶囊

**适用场景**：深色 / 复古皮肤，或底图色彩浓、糖果圆压不住时；默认仍用 4.2。

深底盘的作用是在碎底图上"立住"——浅色底图路网 / 水系 / 绿地很碎，空心描边图标会糊在里面。

- **底盘**：36×36、`border-radius:13px`、实心 **深墨绿 `#10231F`** + `box-shadow: 0 0 0 2.5px var(--c)` 类型色描边 + 投影。
- **牌内**：类型**线性 glyph**（内联 SVG，`stroke` = 类型色、`stroke-width:2.7`、圆头圆角），再配一条**白色短棒 / 断口**
  ——"主色线条 + 白色辅助短线"是线性图标的高级感来源。
  glyph 取形：景点 = 山形折线 + 白短棒；餐厅 = 半圆碗 + 白横；住宿 = 屋顶折线 + 白横；交通 = 船体 + 白竖。
- **编号**：底盘下方**白色胶囊**（`height:18px`、`radius:99px`、`background:#fff`、`font-size:12px / weight 800`），
  `top:29px` 与底盘微重叠 7px。编号是"核对行程"的主角，**必须够大**。
- **几何**：容器 44×50，`iconSize:[44,50]`、`iconAnchor:[20,38]`（锚点落在胶囊中部 = 点位大致就在编号上、牌子在其上方）、`popupAnchor:[0,-42]`。
- `icon(color, typeKey, num)` 三参数：有 `num` 显示编号；无 `num` 时酒店常驻点显示「住」胶囊。
- 编号生成：`seqOf[key||name]` 给**唯一序号**；同一天重复出现的点（如早出 / 晚归的酒店）**复用首次编号**，
  并用 `placed` 去重，否则同一位置会叠成一坨；卡片上给重复点加「↩ 回到这个点」徽章。
- 叠层：`zIndexOffset: 100 + seq` + `riseOnHover: true`，让后出现的压在上层（符合时间先后）。
- 卡片侧：`.tl-dot.seq` 显示**同一编号**、同类型色；点卡片时给对应标记加 `.mk-active`（牌放大 1.14 + 描边发光）。
- 图例补一行「数字胶囊 = 当天游玩顺序 · 牌内图标 = 类型」，否则用户不知道数字是什么。
- 总览页**不要**编号（多天编号会重复且杂乱），用小圆点 + 天标签 popup。

### 4.4 编号字色：先算对比度再改颜色

**实测（WCAG，vs 白底 `#fff`）**：

| 颜色 | 对比度 | 结论 |
|---|---|---|
| 亮蓝 `#00e5ff` | **1.54:1** | 远低于 4.5:1 |
| 亮绿 `#00e676` | **1.67:1** | 换成亮绿只升 0.13，几乎无感 |
| 黄 `#ffab00` | 1.90:1 | 不合格 |
| 红 `#ff5252` | 3.19:1 | 不合格 |
| 蓝 `#448aff` | 3.32:1 | 不合格 |
| **深墨 `#0B2A22`** | **15.35:1** | ✅ |

**正确做法**：字用深墨 `#0B2A22`（15.35:1）+ 一圈 `box-shadow:0 0 0 2px var(--c)` **类型色描边环**保留颜色辨识。

备选：深墨胶囊 + 荧光字（vs `#0B2A22` 约 9.98:1）也可行，但胶囊会和深色底牌糊成一块，丧失"白胶囊作为断口"的层次感。

> **通用规律：荧光色只能写在深底上，白底上必须用深色字。**
> 碰到"颜色看不清"的反馈，**先算对比度再动手**（逐通道线性化后 `(L1+0.05)/(L2+0.05)`），别凭感觉换色。

### 4.5 两个真 bug

1. **CSS 被插进 `@media(max-width:820px){...}` 内部 → 桌面视口全部不生效、手机却正常**。极具迷惑性。
   根因：补丁锚点只写了 media query 的**行首片段**，而这一行后面还有内容 → 在锚点"之前"插入等于插进了 media 内部。
   → **往 CSS 里插东西，锚点必须用完整行，或明确插到整行之后**。
   诊断：读 `getComputedStyle`（关键元素的高度 / 背景是否为空或异常），别靠肉眼看缩略图。
2. **给标记加 CSS 入场动画不可靠**：`animation: ... both` 会**卡在起始帧**（`scale(.25)` / `opacity:0`）
   → 标记只显示成一个小点（后台标签、截图环境都会触发）。
   → **地图标记宁可不做入场动画**，可爱度靠静态造型（形状 + 渐变 + 描边 + 高光）足够。

## 五、皮肤

### 5.1 铁律：地图瓦片绝不加 `sepia` / 大幅降饱和

**地图占屏面积最大，一染色整页就脏。**

实测：同一条路线在 `sepia(.45) saturate(.68)` 下会从鲜红变成**暗砖红**——染色会连路线标识一起毁掉。
更糟的是整页会呈现"黄疸色"（深棕底 + 土黄 + 染黄的地图）。

浅底方案下地图**保持原色**就自然融入；最多 `saturate(.9) brightness(1.03)` 这种极轻调整。

### 5.2 "手账感"配方（按重要性排序）

1. **底要浅**（最关键）：奶油白 `#FDF4E8` / 纸白 `#FAF7F2` / 浅绿 `#EEF3E8`。**浅底 = 手账，深底 = 复古**。
2. **卡片纯白 + 圆角 14–16px + 1.5px 淡描边**（`#F0E2D2` 一类），别堆阴影。
3. **点缀色明快且克制**（小面积）：蜜桃珊瑚 `#E8836B`、砖红 `#B8412F`、抹茶绿 `#7C9A62`、芥末黄。
   切忌全站统一降饱和成"土色系"。
4. **主文字用深棕 / 深墨**（`#6B4F3F` / `#3A342E`），**不要纯黑**；次文字暖灰（`#A78B76`）。
5. **留白 + 字号节奏**：大标题用衬线（`"Songti SC","Source Han Serif SC","Noto Serif SC",STSong,serif`），
   小注释用无衬线，字距略松（`letter-spacing:.3–.6px`）。
6. 弱分隔用**虚线**（`border-top:1px dashed`）比实线更有手账味。

### 5.3 落地色板（实装过）

纸白底 `#FAF7F2` / 面板 `#FDFBF7` / 卡片纯白 + `radius:14px` + 描边 `#EFE6D9` /
主色砖红 `#C2543F` / 蜜桃 `#E8965C` / 抹茶 `#7FA05F` / 雾蓝 `#7C9BC4` /
正文深棕 `#3A342E` / 次要 `#8A7A6A`。**地图瓦片不加任何滤镜。**

**换肤手法**：

- **在 `<style>` 末尾追加一整块同选择器的覆盖规则**（同优先级后者胜出），比逐条改原有规则安全得多；
- 但**原有规则带 `!important` 的，覆盖块也必须带 `!important`**（实测有 4 条：`.card.active-card` / popup 内文字 / zoom 控件 / attribution）；
- 内联在 JS 字符串里的颜色（popup 的 `<span style="color:…">`、总览卡片 `style="color:#fff"`）CSS 覆盖不到，
  **必须改字符串**；白字在浅底上会直接消失。
- 换完**必须用 `getComputedStyle` 实测**（body 底色、tab 激活色、卡片底色、图例底色）——
  源码里残留旧色号不代表没生效，也可能反过来。

### 5.4 能力边界（主动讲清，别硬撑）

- **能做**：配色 / 版式 / 圆角 / 间距 / 字号节奏 / 徽章 / 日历格子——约 90% 观感，纯 CSS。
- **做不了**：**手绘插画**（手绘动物、带笔触的风景）。
  替代：① 自己画几何简笔 SVG（风格统一、可控）② AI 生图出顶部横幅再贴入。

### 5.5 先出对比页再落地

**别靠猜审美，也别盲改正式文件。**

- 同一份 HTML 结构、只换 8 个颜色变量 + 滤镜强度，横排 3–4 列一次截完；
- 把"现状版"也放进对比列当参照，改对了没有一眼可见；
- 用户挑完再改正式文件。

截图参数：viewport 宽 = 列宽×列数 + 间距×(列数−1) + 左右 padding；`deviceScaleFactor:2`；
高度按 `document.body.scrollHeight` 二次设定 + `captureBeyondViewport`。

坑：绝对定位的装饰 SVG 别压到内容区（实测小山压住日历最后一格，显脏）。

## 六、可选：沿路个性化装饰

**默认不做。** 仅当用户明确要求把自己的角色 / 吉祥物之类放到路线上时才启用——这是个性化需求，不是通用做法。

**取点**：把当天所有路段的 `coords` 拼成一个**总点列**，按**索引等距**取 n 个点（如 `0.14 / 0.38 / 0.62 / 0.86`）
→ 天然均匀，比"每段取中点"自然。

- 标记属性：`interactive:false`（不抢站点点击）+ `zIndexOffset:-100`（压在站点下层）
  + `iconSize` / `iconAnchor` 取 `size/2`，让图形正骑在路线上。
- **务必把装饰 marker 也 push 进 `markers` 数组**，否则切天时 `clearMap()` 清不掉
  → **连切两天装饰物翻倍**（实测踩到）。
- 浅色 / 白色图形铺在浅色底图上会"隐身" → ① 深色描边 ② 投影 ③ 尺寸 **≥40px**，
  三条同时满足才立得住；低于这个尺寸只会看出一个"奶白小点"。
- **数量宜少**：实测每天 4 个左右密度合适，再多会盖住路线本身。

## 七、自检（真机，必须做）

### 7.1 语法

抽出所有 `<script>` 丢给 `new Function(code)`——语法不过就是白屏，不用等打开页面。

### 7.2 真机交互

用远程调试端口（如 `9222`）加载 `file://` 页面，回传 JSON：

- `L.version` 是否存在
- `.leaflet-marker-icon` 数量、`path.leaflet-interactive`（折线）数量
- **编号序列**：`.mk` 里的 `.mk-pl` 文本 join，与卡片侧 `.tl-dot.seq` 文本逐一对上；
  同时核对 `.mk` 数量 == `.mk-pl` 数量（每个标记都得有编号或「住」胶囊）
- 读一次 `.mk-pl` 的 `getComputedStyle().color`——**验证配色补丁真的落地了**
- （仅做了装饰时）**连切两天装饰物是否翻倍**
- **真点一次交互**（tab / 票约 / 全屏）——"路由缺分支"这类 bug **光读源码发现不了**
- `Runtime.exceptionThrown` 是否为 none
- 手机宽度下读 `getBoundingClientRect`，确认图例没压住 Leaflet 版权行

### 7.3 行程自检：地标覆盖率

排完每天的点，**逐个核心地标反问一遍：「这一天到底有没有真的到过它？」**

只把地标安排成"顺路经过 / 最后去吃饭"是最常见的隐形破口。

- **典型症状**：点名要去的 A（如"西湖边"），全天行程其实都在 A 的侧面 / 外围打转
  （绕湖西侧、山门外、古城外围），只有晚饭"在它附近"。
- **正确做法**：把地标单独做成一个**有明确时段的地图节点**，并优先安排在它**人最少的时段**
  （多数是清晨开门前后 1–1.5 小时）。
- **反查手法**：在地图页上按天看折线是否**真的触达该地标坐标**；只看卡片文案容易自欺。
- **规律**：热门点清晨去，人一多就撤——正确结构是「清晨打时间差的经典点 → 之后转冷门段」，
  而不是"下午先冷门、傍晚顺路扫一眼经典点"。
- 时段衔接要能自洽：例（杭州）6:15 湖滨集贤亭 → 7:00 断桥白堤 → 8:20 灵隐
  （因 **8:00 前网约车可直达灵隐门口**，8:00 后管制只能外围换乘）→ 下午转湖西冷门段。

### 7.4 两个手机宽度下才暴露的坑

- ⚠️ **图例框会压住右下角的 Leaflet 版权行**：390px 宽实测重叠 **434px²**
  （图例 `311×53` @left10/bottom364、版权 `131×17` @left259）。
  从缩略图肉眼看不出，要**读 `getBoundingClientRect` 判交叠**才量得准。
  修法：`.leaflet-bottom .legend-box{margin-bottom:22px}`
  （必须带 `.leaflet-bottom` 前缀或 `!important`——Leaflet 自带的 `.leaflet-bottom .leaflet-control{margin-bottom:10px}` 特异性更高）。
- ⚠️ **`fitBounds` 的 padding 要跟着标记造型走**：左上角编号标会凸出图标包围盒，padding 40 时贴边标记会被裁，改 **64**。
  另注意常驻标记可能在当前视野外，检查"标记是否被裁"时要先判**标记中心是否落在容器内**，否则屏外标记会被误报成"越界"。

## 八、迁移到第二条线路

同源的线路文件（只有数据不同、模板相同）可以直接**照搬补丁**。按顺序走，一次写盘、跑完回读（手法见附录）。

1. **先诊断，别猜锚点**：写个脚本数一遍每个待替换字符串在目标文件里的**命中次数**，全部必须 = 1 才动手。
   同源文件也会有差异，实战踩到的两处：
   - 注释错字不同（一个文件写「荧」光、另一个写「萤」光）→ 锚点带上注释就会失配；
   - 有的文件还在用 CDN 版 Leaflet，有的已内联 → 替换清单不同。
2. **锚点优先选结构唯一的整行 / 整块**（`.mk{…}` 整段、`const TYPES = {…};` 整块），不要只抓一行里的一小段。
3. **日配色要逐条锚定并修撞色**：用 `date:'…', title:'…', color:'#xxx'` 组合做锚点
   （同色出现两次时单靠色值会误替换）。实战踩到过 **D1 与 D6 撞色**，迁移时顺手分开。
4. **旧色残留判据**：替换完先数残留，逐条看上下文——只要都在**被皮肤块后写覆盖**的规则里就安全
   （带 `!important` 的，皮肤也要带 `!important`）。判据是「**后写 + 同特异性或更高**」，不是"源码里搜不到了"。
5. **Leaflet 本地化（CDN → 内联）**：从已内联的同源文件里抽两段贴过去——
   - CSS = 首个 `<style>` 到首个 `</style>` 之间的内容（就是 leaflet.css）；
   - JS = 那段开头含 `Leaflet 1.9` 的 `<script>…</script>`。
   然后把 CDN 的 `<link>` 与 `<script src>` 整行换掉。
   验收：`performance.getEntriesByType('resource')` 里不应再有 unpkg / jsdelivr（高德瓦片域名不算）。
6. **数据缺口要如实报告，别顺手"补"**：某条线路 D1 没有任何路线键（整天不画线、也就不撒装饰）
   可能是**原有数据缺口**。核实办法：对改动前的备份跑同一段统计脚本，"改前改后一致"即判定不是自己改坏的。
7. **「票·约」页 / 全屏地图的迁移：不只是搬 CSS，还要改路由**（见 `delivery.md`）。
8. **预约类信息每次都要重新实查**（见 `delivery.md`）。
9. **按关键字给日子打标签要收窄条件**：如 `t.indexOf('博物馆')>=0 ? '抢省博' : '预约'`
   会把别的博物馆也误标成"抢省博"→ 必须用能唯一定位的那段文字。凡按关键字打标签都要检查是否可能命中同类项。
10. **住宿 / 动线变更后的重建清单**（用户改了酒店必跑）：见 8.1。

### 8.1 住宿或动线变更后的重建清单

用户把住宿订到别处（尤其换了城区 / 跨江）时，**别只改 `HOTELS`——动线全得跟着改**：

1. 查清**住宿真实坐标 + 最近地铁站 + 步行距离**（地图 App 详情页的"附近-地铁站"栏最准）。
2. 改住宿的 key / 坐标，**同步替换每日序列里的住宿节点**（D1 起终点、D2/D3 起终点、出发段）。
3. **必须重跑路径计算**：起终点一变，相邻点对的 key 全变，不重算就 `MISSING_ROUTES` 一大片。
4. 重写受影响天的 `route` 文案与每个节点的 `conn`（交通衔接）——
   **跨城区的住宿会让某些天从"步行 10min"变成"跨江 40min"，这种代价要在卡片里明说**，
   别让用户到现场才发现。
5. 重算后看**吸附道路名**，反查新坐标对不对。
6. 自检脚本里的"旧占位名"校对串一并更新，并加一条残留检查（必须为 0）。

## 附录：改文件的手法（一次写盘 + 命中校验）

所有改动写成一个补丁脚本，`str.replace` **一次性写盘**，
每个替换先校验命中次数（≠ 期望就整体中止并报告），跑完回读关键字核对。改前自动备份。

- `orig_len = len(s)` 这类变量别漏定义：**写盘后报错会导致"文件已改、报告没出"**。
- **锚点必须唯一**：`\n</style>` 这类可能在文件里命中多次（leaflet 自带 style 块 + 自己的），
  命中数 ≠ 1 就会被跳过（实测 CSS 整块没插进去）→ 用带业务关键字的完整锚点。
- 同一文件多处改动**绝不并行发多个 Edit**（会静默丢改动），脚本一次写盘最稳。
- 改完**必须回读**核对关键字；远端部署 / 上传后同样要回读远端内容与文件大小，不能只信"上传成功"。
